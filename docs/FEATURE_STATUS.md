# Feature status

Status describes implemented behavior, not certification for a live marketplace. No provider sandbox credentials, production country decisions, public DNS, SMTP, or TLS edge were available. Those services have not been represented as live.

| Stage / capability | Delivered behavior | Verification / limitation |
|---|---|---|
| Core: accounts and roles | Registration, email tokens, host-only sessions, CSRF/origin checks, vendor membership, catalog/fulfillment/finance/manager roles and host staff management | API-tested isolation and catalog redaction. Password reset and MFA are not implemented. |
| Seller onboarding | Public application; expiring email-bound invitation; policy acceptance; approval, changes, rejection and suspension; setup checklist | Both local paths tested. Provider eligibility remains separate from host approval. |
| Catalog | Product/variant editor, stock and regular/sale prices, shared server draft autosave with optimistic conflicts, local fallback, image upload, preview, moderation, duplicate/archive/bulk-price API | Upload signatures, row versions, moderation and inventory tested. Bulk-price and custom CSV column mapping are API capabilities; the UI uses canonical CSV columns. |
| Shopping | Responsive editorial home, categories, search/filter/sort/pagination, seller pages, wishlist, product variants, reviews and related products | HTTP and data verified. Browser visual, mobile, focus-trap and keyboard QA remains unexecuted because Browser automation was unavailable. |
| Multi-seller checkout | Guest flow; grouped shipping; exact coupon/tax/commission allocation; atomic reservations; one parent and scoped suborders; failure preservation; partial status; signed-event reconciliation; scoped tracking and verified account linking | Mock HTTP flows tested. No provider-hosted wallet or live checkout was tested. |
| Accounting | DECIMAL snapshots; decimal-safe minor units; commission precedence; balanced append-only capture/refund/transfer/adjustment entries; signed CSV statement | JMD example, rounding, replay and balances tested. Processing fees remain unknown unless actually reported; no invented bank payout. |
| Fulfillment and returns | Validated transitions; tracking outbox; partial item shipments; cancellation of unshipped paid quantities; return approval, receipt, quarantine/restock; host-controlled refunds | Tested with mocks. Cancellation creates a refund review item; original delivery charges are not automatically refunded. Vendor nonacceptance is handled through cancellation/support review, not an automatic refund timer. |
| Expansion: storefronts | Published structured themes, mobile/desktop banner sources, store paths, subdomain tenant resolution, custom DNS challenges, CNAME validation, trusted TLS checks and six-hour monitoring, secure central cart handoff | Handoff replay and host rejection tested. Public certificate issuance needs a configured edge; runbook provided. No domain was provisioned. |
| SEO | Server HTML product/store metadata, canonical URLs, JSON-LD, sitemap and robots | Applies to the built Express server; Vite development HTML is not server-rendered. Product descriptions remain client-rendered. |
| Expansion: imports and delivery | CSV size/row limits, encoding selection, preview errors, duplicate policy, idempotent confirmation; country/region/postal-prefix zones, rates/free thresholds/pickup | API-tested, including plan-limit enforcement. No carrier-rate, label, dimensional-weight, or tax-service integration. |
| Expansion: recovery | Explicit abandoned-cart consent, delayed reminder, single-use recovery and opt-out; transactional email outbox | Local email previews tested. SMTP delivery is externally unverified. |
| Growth: subscriptions | Stripe subscription Checkout; verified current subscription state; base 100 / growth 1,000 active-product entitlements across editor and imports | Entitlement enforcement tested. Actual recurring billing awaits sandbox credentials and price configuration. No customer billing portal is implemented. |
| Growth: promotions, loyalty, referrals | Scheduled labeled promotions, earned points, personal one-use reward coupons, cumulative refund adjustment, referral attribution with buyer-hash uniqueness/self-referral exclusion | Loyalty ownership/replay tested. Referrals provide attribution only; no automatic referral reward or fraud-scoring service. |
| Growth: analytics | Explicit optional browser consent; view/add-to-cart/checkout events; UTC 30-day host analytics API; paid-provider/currency-separated aggregates | Consent rejection tested. Dashboard metrics are limited summaries, not a full conversion attribution/reporting suite. |
| Financial exceptions | Verified Stripe/PayPal dispute retrieval, provider balance journals, dispute queue, documented manual balance adjustments; bounded transfer/refund retries and reconciliation states | Synthetic Stripe-style dispute fixtures tested. Evidence submission stays in provider dashboards. PayPal balance/fee/payout reports are not imported; finance must reconcile them separately. |

## Outstanding launch work

1. Select and confirm operating country, seller countries, legal charge/liability model, tax treatment, settlement currencies, commission and payout/return policy. USD, US sample sellers and 10% are development fixtures, not eligibility decisions.
2. Execute real Stripe Connect and approved PayPal multiparty sandbox scenarios, including refunds after transfer, payout failures, partial PayPal capture, subscription renewals and chargebacks. Complete country/partner approval before live configuration.
3. Configure SMTP, public DNS, TLS edge/certificate persistence, backups, monitoring, support contact and approved legal content. Sample policy/support copy must be replaced before launch.
4. Complete browser/mobile/accessibility QA. Audit identity recovery, MFA for privileged roles, operational alerting and public-scale performance before exposing real customers.
5. For PayPal settlement reporting, recurring billing self-service, fully itemized printable reports, provider fee imports, and automatic nonacceptance escalation, additional implementation remains. Existing APIs and ledgers do not pretend to supply these functions.

These are explicit delivery limits. The project is a working local implementation, not a declaration that every production acceptance criterion has been met.
